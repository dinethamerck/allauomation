## 1. Overview & Test Scope

The **Report Reviews Module** is an essential diagnostic and clinical workflow component within Amerck Care EMR. It enables physicians, radiologists, and clinical specialists to manage, review, verify, and dispatch diagnostic investigation reports (e.g., Blood tests, Imaging, Ultrasound, Histopathology) uploaded for telehealth patients.

### Key Functional Capabilities:
1. **Centralized Reviews Directory (`/admin/telemedicine-reports`):**
   - High-level tracking of all patient diagnostic reviews: Report ID, Patient ID, Patient Name, Attending Doctor, Status, and Date.
   - Live pagination controls with page status indicators.
2. **Patient Identification & Global Search Modal:**
   - Universal search dialog accepting Sri Lankan National Identity Card (NIC) numbers (9-digit with V/X or 12-digit format) and 10-digit mobile phone numbers.
   - Input format validation rejecting invalid query strings.
   - Patient match card selection with immediate local practice roster synchronization (`POST /patients/addPatientsForLocal`).
   - Registration redirect for new patients (`/admin/telemedicine-reports/patients/new?query=...`).
3. **Patient Review Detail Workspace (`/admin/telemedicine-reports/patients/[id]`):**
   - Patient demographics, unique Report ID reference (`RR-XXXXX`), and lifecycle status (`DRAFT`, `PENDING`, `COMPLETED`).
   - Doctor assignment and clinical review history timeline.
4. **Diagnostic File Upload & Attachment:**
   - Multi-format file uploader supporting `.pdf`, `.txt`, `.jpg`, `.png` up to 10MB per file.
   - File attachment validation and confirmation workflow.
5. **Patient Notification & Report Dispatch:**
   - Final report dispatch action (`Send to Patient`) updating session status and notifying patients via SMS/portal.
6. **Cross-Module Navigation:** Direct integration with Telemedicine Kanban Board, Prescription (Care View), and Inpatient Admissions.

## 2. Test Execution & Credential Guidelines

> [!IMPORTANT]
> **Credential Security Standard:**
> - Provider credentials must **never** be hardcoded directly into shared test scripts, public repositories, or plain-text logs.
> - Store credentials strictly in `.env` files protected by `.gitignore`.
> - Automated test suite utilizes session storage state at `playwright/.auth/user.json` generated by `tests/auth.setup.js`.
