## 1. Overview & Test Scope

The **Telemedicine & Virtual Consultations Module** provides real-time virtual care dispatch, queue orchestration, patient consultation management, and clinical report review. It serves as the primary hub for remote medical encounters in the Amerck Care EMR platform.

### Key Functional Capabilities:
1. **Interactive Kanban Session Board (`/admin/telemedicine`):**
   - Real-time 5-stage patient consultation pipeline:
     1. **Pending:** Consultations awaiting payment confirmation.
     2. **Waiting:** Paid consultations ready in the waiting room for doctor pickup.
     3. **Assigned:** Consultations dispatched to a specific attending physician.
     4. **In Consultation:** Active virtual video/audio consultations currently in progress.
     5. **Completed:** Concluded consultations with finalized clinical notes and prescriptions.
2. **Provider Availability Status:** Real-time Online/Offline switch updating provider dispatch availability (`POST /telemed/admin/online-status`).
3. **Audio Notification System:** Sound ON/OFF switch alerting doctors to incoming waiting room patients.
4. **Historical & Future Date Filtering:** Flatpickr date selector enabling instant retrieval of past records or upcoming virtual appointments.
5. **Telemedicine Report Reviews (`/admin/telemedicine-reports`):**
   - Centralized review table tracking Report ID, Patient ID, Patient Name, Attending Doctor, Review Status, and Date.
   - Patient search modal to upload and associate external lab/diagnostic reports with patient records.
6. **Cross-Module Navigation:** Direct integration with Admissions, Prescription (Care View), and Patient Directory.

## 2. Test Execution & Credential Guidelines

> **Credential Security Standard:**
> - Provider credentials must **never** be hardcoded directly into shared test scripts, public repositories, or plain-text logs.
> - Store credentials strictly in `.env` files protected by `.gitignore`.
> - Automated test suite utilizes session storage state at `playwright/.auth/user.json` generated by `tests/auth.setup.js`.
